# 目录与笔记阅读密码契约

## 功能边界与升级

阅读锁保护支持此功能的客户端内的查看、搜索、历史和导出入口。正文仍按现有同步模型存放在服务端数据库与客户端离线缓存中，图片继续使用现有上传 URL；本功能不提供正文加密、端到端加密或数据库文件访问防护。已登录账号仍通过原有同步接口取得正文与密码校验元数据，离线设备按最后同步到的锁状态校验密码。

网页版通过 Web Crypto 验证阅读密码，需要 HTTPS 或 localhost 安全上下文；不支持的环境会显示提示，可切换到 HTTPS 站点或桌面客户端。

部署时须同时升级服务端及所有使用该账号的客户端。旧客户端不理解阅读锁字段，无法执行阅读限制；单独升级服务端不能约束旧客户端。服务端启动会为旧数据库的 `notes` 与 `folders` 表添加可空的 `reading_lock` 列，原有数据默认无锁。修改阅读密码、取消密码和重设密码须联网；离线状态不排队保存密码变更。

## 同步字段

所有笔记、目录响应（包括普通写入回执、409 冲突内容、增量拉取、WebSocket upsert、删除/恢复）均返回 `readingLock`。无锁为 `null`，有锁为：

```json
{
  "salt": "16 字节随机盐的 32 位十六进制字符串",
  "hash": "32 字节派生值的 64 位十六进制字符串",
  "iterations": 210000,
  "revision": "服务端生成的 UUID v4"
}
```

派生方式为 `PBKDF2-HMAC-SHA256(UTF-8 密码, hex 解码后的 salt, 210000, 32 字节)`。密码不做 trim，长度为 6–128 个 JavaScript 字符单元。每次设定或重设都产生全新随机盐和 revision；解锁凭据必须绑定实体 ID 与当前 revision，只保存在客户端内存，不能同步或持久化。

目录锁由客户端沿祖先目录逐层验证，软删除祖先仍参与回收站内容保护；笔记独立密码在目录密码后额外验证。当前设备的解锁不改变服务端元数据或其他设备的解锁状态。

## 密码变更

```text
PUT /api/notes/:id/reading-lock
PUT /api/folders/:id/reading-lock
Authorization: Bearer <登录 token>
X-Client-Id: <当前设备 ID>
```

```json
{
  "password": "新的阅读密码；取消时传 null",
  "accountPassword": "账号登录密码；重设或取消必填",
  "baseLockRevision": "当前 readingLock.revision；首次设置时传 null"
}
```

首次设置无须账号密码；修改已有密码、取消密码必须校验当前账号登录密码。成功返回更新后的完整实体，增加实体 `version`、用户同步 `seq` 和 `updatedAt`，并向其他设备广播标准 `note:upsert` 或 `folder:upsert`。

该接口仅更新阅读锁列，不修改正文、目录关系或历史快照。比较依据为 `baseLockRevision`，不是正文 `baseVersion`；密码计算结束后会在数据库事务内重读实体并再次比较，避免并发重设覆盖。正文保存仍使用既有 `baseVersion` 乐观锁机制。

| 状态 | 含义 |
| --- | --- |
| 200 | 密码变更完成，响应为完整笔记或目录 |
| 400 | 密码类型/长度错误、缺少版本、UUID 格式错误 |
| 401 | 登录无效，沿用现有账号登录流程 |
| 403 | 账号密码不正确；客户端不得因此退出登录 |
| 404 | 实体不存在或属于其他账号 |
| 409 | 锁状态已变化；`{ conflict: true, note/folder: 最新实体 }` |
| 429 | 超过限流，响应 `Retry-After` 秒数 |

限流按账号执行：最多 30 次密码操作/分钟，账号密码错误累计 5 次后在 5 分钟窗口内限制重试。限流独立于登录，不因阅读密码重设失败使现有登录失效。

普通实体 POST/PATCH 禁止出现 `readingLock`、`reading_lock`、`password`、`accountPassword`、`baseLockRevision`，即便值为 `null` 也返回 400。客户端应显式选择可修改字段，不把完整实体直接发送为写入请求。

## 冲突、恢复与客户端时序

创建冲突副本时只提交 `conflictOf` 指向同账号源笔记。服务端强制继承源笔记当前独立阅读锁及所在目录，客户端不能指定密码校验值或通过指定根目录丢失目录保护。来源不存在或跨账号返回 404。历史恢复、普通内容保存、软删除与撤销不会覆盖当前阅读锁。

客户端应在请求变更密码前结算输入法、标题与正文草稿并确认同步成功；密码请求不进入离线队列。收到远端锁或目录关系变化时，即使存在本地未保存草稿，也应立即刷新权限元数据而保留草稿；迟到回执不得覆盖更新的锁、目录关系和授权状态。异步校验和网络回执需检查账号世代，避免跨账号生效。

离开阅读范围、收起受保护目录、进入后台、退出账号或重新启动后撤销当前范围授权。目录/笔记密码 revision 改变时，之前的授权立即失效。目录移动同样可能改变继承范围，客户端必须重新计算权限链并清理不再属于当前范围的授权。

## 验证

运行 `npm run test:reading-lock`，覆盖旧库迁移、鉴权归属、密码派生、输入验证、并发重设、普通接口防覆盖、增量同步/广播、冲突副本、历史恢复、软删除及限流。既有服务端回归仍使用 `npm run test:e2e`（需先启动隔离测试服务）。

从仓库根目录运行 `npm --prefix app run test:unit` 验证客户端锁状态、同步竞态及密码操作；先 `npm --prefix app run build`，再 `npm --prefix app run test:reading-lock`，使用隔离的无头 Chrome 验证桌面、手机、回收站及密码管理流程。
